OrderSystem API

This is a simple .NET 8 Web API for managing customers, products and orders.

Features
- CRUD endpoints for Customers, Products and Orders (including order items)
- SQLite persistence via Entity Framework Core
- Seeded initial data: 5 customers, 10 products and 10 orders
- Swagger UI for exploring the API
- Dockerfile and docker-compose for running the app in Docker

How to run locally (Visual Studio)
1. Open the solution OrderSystem.sln in Visual Studio 2022/2026.
2. Set the startup project to src/OrderSystem.
3. Build and run (F5). The app will be available at http://localhost:5000 (or a port assigned by VS). Swagger UI: http://localhost:5000/swagger/index.html

Notes:
- On first run the application will apply EF migrations and create the SQLite database file orders.db in the application working directory.

How to run with Docker

Prerequisites: Docker Desktop

1. Build and run with docker-compose:
   docker compose up --build

2. The API will be available at http://localhost:5000 and the SQLite file will be persisted under ./data/orders.db

Project layout
- src/OrderSystem: main Web API project
- Dockerfile, docker-compose.yml: docker configuration

API endpoints
- GET /api/customers
- GET /api/customers/{id}
- POST /api/customers
- PUT /api/customers/{id}
- DELETE /api/customers/{id}

- GET /api/products
- GET /api/products/{id}
- POST /api/products
- PUT /api/products/{id}
- DELETE /api/products/{id}

- GET /api/orders
- GET /api/orders/{id}
- POST /api/orders
- PUT /api/orders/{id}
- DELETE /api/orders/{id}

Notes on design
- The application is implemented as an "all-in-one" monolithic Web API for simplicity (API + data access in one service).
- The DbContext is configured to apply pending migrations at startup to ensure the schema and seed data are created automatically.

If you want a real migration file generated by `dotnet ef migrations add`, you can run the EF tools locally, but the project already includes an initial migration used on startup.
